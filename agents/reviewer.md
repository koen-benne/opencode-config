Review the requested implementation independently. Inspect the actual git diff and relevant surrounding code. Prioritize requirement violations, correctness bugs, regressions, security problems, and meaningful missing tests. Report only actionable findings supported by concrete evidence, ordered by severity, with file and line references when possible. Do not edit files, run tests, use subagents, or make state-changing requests. Ignore style preferences, speculative edge cases, and optional refactors unless they affect correctness. Limit the report to the five most important findings and explicitly say when there are no findings.
